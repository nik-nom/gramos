# GramOS v4.0 — clear page editors, 12 bottom logos and responsive alignment

This release updates the **existing GramOS project** on its current stack (Node, vanilla JS, Supabase and Vercel). **Do not create a separate repository, database or website.** The existing loading screen is untouched. This is a source-code release; it has **not** been published to your Vercel domain.

## What changed

- **Separate Home page editor**: open the village in `/admin`, then **Home page**. Clearly numbered panels cover the main banner, the shared scrolling message below the navigation, welcome text, section titles, menu text, weather box and homepage section order. Optional fields are folded into “Edit text in this area” controls, rather than one enormous form.
- **Simple, page-first admin navigation**: the sidebar now groups **Edit website pages**, **Whole website**, and **Add photos, cards & records**. From the page editors, content shortcuts take you straight to the relevant news, gallery, notices, projects or other records.
- **Bottom logos & footer editor**: available under **Whole website → Bottom logos & footer**. Add, upload, remove and reorder up to **12 separate logos**. Every logo occupies a separate responsive grid cell with `object-fit: contain`; natural proportions are preserved. A previously saved single footer logo remains supported.
- **Bigger preview**: homepage and footer editors have a wide embedded preview (desktop iframe height 680px), plus **Open full page**. The preview shows *saved* changes; click Save first.
- **One shared scrolling announcement**: edit Marathi and English text under **Home page → Scrolling message — every page**. All pages of that **same village** use that message. Villages remain independent; the same message is *not* forced across different villages.
- **Long text without overlapping boxes**: content cards can grow vertically and wrap long text. Long homepage project descriptions show a **Read more / पूर्ण माहिती पहा** disclosure for the full text. News and other panels are allowed to grow as needed.
- **Narrow-screen improvements**: public branding wraps instead of colliding with the navigation, and the menu switches to its mobile layout before links run out of room.

## How to replace the project on your Mac

### Recommended: full ZIP

1. Extract **`GramOS_v4.0_Complete_Node.zip`** to a *new* folder and keep your existing repository backed up.
2. Copy your existing **`config.js`** (if customized), environment settings, and other private deployment configuration into this folder. **Do not commit secret keys.**
3. In Terminal:

```bash
cd ~/Downloads/GramOS_v4.0_Complete_Node
npm test
npm run dev
```

If you extracted to a differently named folder, use that folder name in `cd`.

Then check `http://localhost:8000/admin/login`, select your village, open **Home page** and **Bottom logos & footer**.

### Changed-files ZIP (only when your original project is exactly v3.9)

Back up the v3.9 repo first; then extract `GramOS_v4.0_Changed_Files_Only.zip` **inside your existing project root**, keeping folder structure and overwriting matching files. Do *not* drop the changed files into a nested folder. Run `npm test` before deploying.

For an existing GitHub/Vercel-linked repository after verifying locally:

```bash
git status
git add .
git commit -m "Upgrade GramOS admin to v4.0"
git push origin main
```

If your branch is not named `main`, replace it with your active deployment branch. If the Vercel project automatically deploys GitHub commits, check the deployment there. If you deploy through Vercel CLI instead, use your existing linked project after verifying a preview deployment.

## Saving content

1. **Home page**: edit the banner, scrolling message and headings, then **Save homepage**.
2. **Bottom logos & footer**: click **Add another logo**, upload or paste each logo URL, arrange using the arrows, then **Save logos & footer**. You can add 10, 11 or 12. Delete unwanted rows with **Remove**.
3. **Village information**: edit the village's main header logo, name, address and phone number; these are separate from the 12 bottom logos.
4. Open **Open full page**, or reload the public site to review the *saved* result. Public content records still require their own **Published** status.

## Data and security

- **No Supabase schema migration**. Multiple logos are saved as a JSON string array in the existing `villages.site_settings.footer_logos`; the first item is mirrored to the legacy `footer_logo_url`. Each village is edited independently through its existing RLS-protected update path.
- Previously saved single-logo sites continue working until replaced. Image uploads continue to use the existing village media storage workflow.
- The values for announcement, footer, logos and homepage are stored in the corresponding village's data, not in a shared global site configuration.
- Validated image URLs must be HTTPS; unsupported script URLs are not rendered.

## Verification and limitations

- The **36 automated Node tests passed** (including the new v4.0 independent-save and 12-logo tests).
- An **offline Chromium browser layout check passed 48 combinations**: Home, Footer, Village information, About, News, Contact, Gallery admin editors and public homepage at widths 320, 390, 650, 820, 1024 and 1440 pixels. It checks horizontal overflow, visible bottom logo blocks, logo count, and image scaling.
- To repeat optional browser layout QA, install Playwright and Chromium in your own test environment, then run `node tests/v40-snapshots.mjs` and `python tests/v40-browser-static.py`. Those checks use **mock village data**, no Supabase login.
- **Not verified in this environment:** production authenticated admin save, actual Supabase image upload, Safari rendering, or live Vercel deployment. Test the signed-in upload-and-save flow once on your own Vercel preview before publishing. Do not treat local mock testing as production verification.
