# GramOS v4.6 — शासकीय योजना + नोटीस बोर्ड reference pages

**Target:** Existing GramOS **v4.5 Node.js** project, NOT the earlier Next.js multi-tenant source.

This version changes the public schemes and notice-board **template defaults**, the related admin editing shortcuts and the public long-card modal. Existing village rows, logos, footer, permissions, navigation, about-page reference content, Lokseva pages and all three V Swaraj PDFs are unchanged.

## What is included

### Schemes / शासकीय योजना

- Same heading, subtitles and three tabs as the supplied 22 November Shamvadi screenshots: `सर्व योजना`, `वैयक्तिक लाभाच्या योजना`, `सार्वजनिक विकासाच्या योजना`.
- Three built-in individual-benefit cards: `प्रधानमंत्री आवास योजना`, `रमाई आवास योजना`, `पंडित दीनदयाळ उपाध्याय घरकुल जागा खरेदी अर्थसहाय्य योजना`.
- Two public-development cards: `यात्रास्थळ विकास कार्यक्रम`, `जल जीवन मिशन`.
- Core descriptions, headings and lists have been transcribed from visible portions of the screenshots, including the repeated water-supply programme description that appears on both public-development cards. Content outside the photographed area was **not invented**. This is *reference text from the user's screenshots*, not a current governmental eligibility certification.
- For long cards, a single `संपूर्ण माहिती पहा` button opens a full modal. The visitor never needs to scroll inside a small card. All headings, bullets and scheme details remain available; nothing is discarded. Without JavaScript, the full text remains visible on the card.
- New village websites display these templates without adding database rows. Publishing a village's own `schemes` record with exactly the same slug replaces only that card in that village; any new slug adds a card. Drafts are private and only visible in an authenticated preview.

### Notice Board / नोटीस बोर्ड

- Existing four tabs remain: Notices, Financial Reports, RTI, and Government Resolutions.
- Two RTI reference titles from the screenshot are present: `खंडपीठ आदेश` and `माहिती अधिकार १ ते १३`.
- **The actual RTI PDFs have not been provided.** An earlier file with an RTI-like filename contained a general Lokseva application form, so it must not be presented as either RTI document. The template displays a non-clickable `PDF अद्याप अपलोड केलेले नाही.` indicator instead of fake downloads.
- Super Admin or village Admin can open **Notice Board → RTI reference titles → Attach PDF**. After uploading a *correct public PDF* and publishing the corresponding item, that village gets its own active Download button. Other villages are unchanged.

### Marriage-registration PDF

`V_Swaraj_Gramsoft_Form_3(2).pdf` uploaded with the screenshots has the same SHA-256 checksum as the existing v4.5 bundled `assets/forms/V_Swaraj_Gramsoft_Form_3.pdf`. It was intentionally not replaced or modified.

## Installation

1. Back up your current **v4.5** repository and copy any uncommitted work elsewhere.
2. Extract `GramOS_v4.6_Changed_Files_Only.zip` in the **root of v4.5**. Overwrite matching files. For a clean install, use `GramOS_v4.6_Complete_Node.zip` instead.
3. Run:

```bash
cd /path/to/your/GramOS-repository
npm test
npm run dev
```

4. Open:
   - `http://localhost:8000/demo/schemes` — check all three tabs, five cards, and the More dialogs.
   - `http://localhost:8000/demo/notices?noticeTab=rti` — check the two reference titles and disabled PDF placeholders.
   - `http://localhost:8000/demo/services` — check that the Lokseva layout and all three PDFs remain unchanged.
   - Your own village via `/v/YOUR-VILLAGE-SLUG/schemes` and `/v/YOUR-VILLAGE-SLUG/notices`.
5. In the authenticated admin, open **Government Schemes → Built-in schemes** to customize one. Save as Draft; verify it is visible only through an authorized preview. Publish only after approving accuracy. Test the same village in public and confirm a second village remains unchanged.
6. Open **Notice Board → RTI reference titles** and upload each corresponding approved PDF, then publish the record. Do not substitute a general application form or fake PDF.
7. Push to your existing GitHub/Vercel repository and test a **Vercel preview deployment** first. Promote only when tests pass.

## Database status and rollback

**No SQL migration, Supabase write or database ownership change is needed or performed.** Existing `gramos-clean` `villages` and `content_items` tables, RLS and publication rules remain in use. Screenshot defaults are JavaScript constants, not new database data. Roll back by redeploying v4.5; village-specific records created after installation remain in Supabase and may require separate review.

## Verification and limitations

- `npm test`: all 40 chained automated test scripts pass, including v4.6 checks for separate village domains, matching-slug overrides, draft isolation and absent-document behavior.
- The marriage-registration PDF was SHA-256 compared and is unchanged.
- Local Node.js `/demo` route returned HTTP 200. Chromium screenshot generation failed to complete in this container, so actual pixel-level mobile/desktop browser verification and authenticated Supabase upload/publish tests **still need staging confirmation**.
- Content amounts and programme details in the reference screenshots may be outdated or inconsistent. In particular, the two public-development schemes show repeated text in the source screenshots. Please review official/current scheme rules before public launch. Nothing has been changed on your production Vercel site.
