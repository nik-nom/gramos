# GramOS v4.8.1 — per-village predefined custom domain

## What this changes

Admin → **Choose village → Custom domain / कस्टम डोमेन** now has:

- A predefined, immutable route displayed as `/v/<village-slug>` and a full `https://gramos-public.vercel.app/v/<village-slug>` link.
- A domain field displaying **— —** until you add a real domain; e.g. `lohegaon.in` (just the hostname, not `https://`).
- A status list, **Verify & activate**, and **Remove**. Only a **Super Admin** may use these actions.
- A domain remains **pending** until Vercel confirms (1) domain ownership in the **gramos-public** project and (2) working DNS. This is checked by the admin's server; the public client cannot activate domains.
- After activation, `https://gramos-public.vercel.app/v/lohegaon` responds with a **307 (non-cacheable)** redirect to `https://lohegaon.in/v/lohegaon`. The `/v/<village>` path stays intact. The 307 is intentional: a changed or removed domain will not leave a sticky permanent browser redirect.
- `https://lohegaon.in/v/shirpur` returns 404. The domain root `/` remains 404, as requested; no village directory.
- Per-domain `/sitemap.xml` lists **only the matching village's published pages**. Pending/unverified domains are not served. The shared Vercel sitemap omits villages that have an active custom domain.
- Existing village content, Marathi text, logos, PDFs, CSS theme, data records and drafts are not modified by this feature.
- Public visitor forms permit **only** activated village domain(s) for that village (plus the configured shared host) after Cloudflare Turnstile verification. Add each new domain to the Cloudflare widget's approved hostnames as well.

- `SUPABASE_PUBLISHABLE_KEY` = publishable key from Supabase API Keys
- `SITE_URL` = `https://gramos-public.vercel.app` (shared Vercel production hostname, NOT a single village's custom domain)
- `PUBLIC_SHARED_HOST` = `gramos-public.vercel.app` (recommended)
- For visitor forms only: `SUPABASE_SERVICE_ROLE_KEY` and `TURNSTILE_SECRET_KEY` (server-side only; never in `config.js` or client JavaScript).

### `gramos-admin` project (Root Directory = `apps/admin`)

- Same `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` and **server-only** `SUPABASE_SERVICE_ROLE_KEY`.
- `VERCEL_API_TOKEN` = a Vercel account token authorized for the **gramos-public** project.
- `VERCEL_PUBLIC_PROJECT_ID` = **the public project's Vercel Project ID**, not the admin Project ID; find it at `gramos-public → Settings → General`.
- `VERCEL_TEAM_ID` = optional team ID if the public project is in a Vercel team.

Never put API secrets in GitHub, screenshots, frontend `config.js`, or chats. Set them in each Vercel project's **Settings → Environment Variables** and **redeploy**.

## Step 3 — Add and activate a domain in GramOS Admin

1. Sign in at `https://gramos-admin.vercel.app/admin/login` as a **Super Admin**.
2. Select a village, choose **Custom domain / कस्टम डोमेन** from the sidebar.
3. The default field is `— —`. Enter e.g. `lohegaon.in` (placeholder example only; the actual domain must be owned by the village).
4. Click **Save / change domain**. If `VERCEL_API_TOKEN` and `VERCEL_PUBLIC_PROJECT_ID` are configured, the server attempts to register it on the Vercel **public** project. Otherwise it stays pending and you must manually add it at `gramos-public → Settings → Domains`.
5. At the village's domain registrar, enter the **exact A/CNAME/TXT records that Vercel displays**. Do not guess an IP address or CNAME; Vercel's requirements may vary.
6. After Vercel reports DNS valid/ownership verified, return to GramOS Admin and click **Verify & activate**. Only then will the database mark the domain active.
7. Test `https://lohegaon.in/v/lohegaon`, `https://lohegaon.in/sitemap.xml`, `https://lohegaon.in/robots.txt` and the original `https://gramos-public.vercel.app/v/lohegaon` (which should redirect to the custom URL).
8. Confirm wrong-village requests like `https://lohegaon.in/v/shirpur` return 404.

**Do not paste a placeholder (— —), an unpurchased domain, or a plain `https://` URL into the domain field.**

## Contact-form key (Cloudflare Turnstile)

The **site key** is public and belongs only in the root `config.js` (`turnstileSiteKey`, then re-run the split sync script). The **secret key** must be entered privately in Vercel `gramos-public → Environment Variables` as `TURNSTILE_SECRET_KEY`.

When adding a village domain, add that hostname to the Cloudflare Turnstile widget's allowed hostnames. The server checks the Turnstile token's hostname against both the configured shared website host and **only that village's activated hostname**. Without this, contact forms on a new custom domain can be rejected.

## Rollback

1. In GramOS Admin remove the custom domain (or disable it server-side); the original `/v/<village>` route will continue to work on the Vercel shared URL.
2. Revert the GitHub commit and redeploy both Vercel projects if needed.
3. Do **not** drop `village_domains` or old Supabase tables as part of an emergency rollback; leave them intact until all active domains are detached and data is backed up.
