# GramOS v3.9 — footer legal notice, editable copyright, Marathi social label

Use the **complete** ZIP if your previous folder has been mixed with older versions. It contains all application source through v3.9; you do not need to merge v2.9/v3.0 updates.

## Public website changes

- The logo below **every** public page stays centered in a white band before the dark footer; the village name/text directly below this logo is removed. The logo's accessible alt text remains intact.
- The four-column dark footer is preserved. Its first column and the Contact page's tabs/cards use the Devanagari label **सोशल मीडिया** (not “समाज माध्यमे” and not English “Social Media” in Marathi content). Legacy default labels are converted automatically without modifying published custom text.
- A legal row is restored **inside the footer, beneath the columns**, with copyright text, optional editable design/development/maintenance credit, and an admin link. The default notice is `© <current year> · हे ग्रामपंचायतीचे अधिकृत संकेतस्थळ आहे.`. No agency or developer name is automatically claimed. Add the correct credit yourself if required.
- All public routes reuse the same `homeBottomLogo` and `homeFooter` renderer, including Home, About, Lokseva, Projects, Yojana, Beneficiary Lists, Notice Board, News, Gallery and Contact.

## Edit copyright/credit and social label

1. Sign in at `/admin/login` and select your village.
2. Open **Village Settings** and scroll to **FOOTER / LINKS & CONTACT**. The fields are:
   - `footer_social_heading_mr` — Marathi footer label; default **सोशल मीडिया**.
   - `footer_social_heading_en` — English footer label.
   - `copyright_mr` / `copyright_en` — complete editable legal/copyright line.
   - `credit_mr` / `credit_en` — optional design/development/maintenance credit shown after the legal line.
   - Other existing footer link, body and contact fields remain editable.
3. Click **Save village settings** at the end of the Village Settings form.
4. Reopen or refresh `/v/<village-slug>` and `/v/<village-slug>/contact` to see the published changes. The public page is fetched from the village's Supabase record; no republishing is needed for village-level settings.
5. To change the Social tab's label independently, open **Contact Page — Editor** and edit `contact_tab_social_mr`, then Save Contact Page.

The demo uses demonstration copy. The real village website does not automatically receive the demo's addresses, images or records.

## Restore from a complete ZIP (recommended)

```bash
cd ~/Downloads
mkdir -p gramos-v3.9-full
unzip -o GramOS_v3.9_Complete_Node.zip -d gramos-v3.9-full
cd gramos-v3.9-full
npm test
PORT=8001 npm run dev
```

Open `http://localhost:8001/admin/login`, `http://localhost:8001/demo` and, if Supabase is configured, `http://localhost:8001/v/shirpur`.

If you already have an unmodified **v3.8** codebase, extract `GramOS_v3.9_Changed_Files_Only.zip` into that project's root. Don't merge over older v2.x or v3.0 folders.

## Deploy to existing Vercel project

```bash
vercel login
vercel link
vercel deploy
# After verifying the preview environment:
vercel deploy --prod
```

Do not commit your service-role key or Turnstile secret. Preserve your existing Vercel environment configuration.

## Database / testing scope

- No schema changes are necessary: the new footer fields use existing `public.villages.site_settings` JSONB, which is saved by the existing authenticated `settingsForm` update path.
- Supabase `villages`, `content_items`, `submissions` and `village_members` have RLS enabled; the `service-documents` PDF bucket and `village-media` image bucket exist. At inspection time there was one published village `shirpur` and no published content records.
- The automated suite now contains 35 scripts. It verifies the new footer social name, safe HTML escaping, image-only bottom band and mock admin persistence to public rendering.
- Chromium offline tests verified Home and Contact on 1440/941/650/390px without horizontal overflow.
- **Not verified:** a signed-in Safari admin save on your deployed Vercel site or its production environment variables. Test those before treating deployment as complete.
- Supabase security advisor still reports leaked-password protection disabled. Enable that option under your project Auth security settings.
