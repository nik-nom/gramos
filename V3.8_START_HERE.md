# GramOS v3.8 — page-bottom logo, true language dropdown, clean footer, PDF downloads

This is the **complete GramOS codebase**, not a patch series. The complete ZIP includes all previous changes through v3.8. Do not merge old v2.9 or v3.0 files over these files.

## Precisely what changed

- **Page-bottom logo**: A separate white region immediately *after* each public page's `<main>` content and immediately *before* the dark `<footer>`. It is NOT inside the footer. Centered on desktop and mobile; the village name appears beneath the image. Home, About, Lokseva, Yojana, beneficiary lists, projects, notice board, news/articles, gallery, contact, and fallback public pages use the same region.
- **Admin upload**: In `Admin → Village Settings`, scroll to **Page-bottom logo — outside the footer**. Upload PNG/JPG/WebP to Supabase village-media (4 MB final size), then **Save Village Settings**. The `footer_logo_url` setting retains its database key for compatibility with previous releases. When empty, it falls back to the village's existing logo. No database migration is necessary.
- **Social Media**: In the footer and the Contact social section/tab, the title is exactly `Social Media` rather than `समाज माध्यमे`. The rest of public page content remains Marathi.
- **Contact Information**: The footer no longer manufactures a `ग्रामपंचायत कार्यालय` address by mixing name, taluka and district. It only displays address, phone, email and office hours when supplied in Village Settings. If nothing is supplied, an honest "add contact information in Admin" message appears. The Contact page similarly avoids inventing a map location.
- **Copyright removed**: There is no copyright row in the public footer. Legacy copyright fields remain untouched in Supabase but are no longer rendered or presented for new edits.
- **Language dropdown**: A real Marathi / English menu is available in the public navbar (and a matching menu in Admin). As previously requested, the public **navigation labels** can switch languages, while the public page content is Marathi-first. On mobile open ☰ menu to see the language chooser.
- **PDF support**: Notice Board and Lokseva Service Forms use real `.pdf` links for their Download actions. The admin's content editor includes a PDF upload input for `notices`, `service_forms`, and `services`, and a link to an existing PDF when one is attached. Valid PDFs are stored under `service-documents/<village-id>/<uuid>.pdf` in the existing Supabase Storage public PDF bucket and their URL is stored in `content_items.external_url` after you save. An item must be **Published** for its download to appear. Non-PDF webpages are rejected as Notice/Form download links. Admin also supports linked PDF service cards.

## Full-project install (recommended if you accidentally merged old releases)

1. Back up your current project folder. **Do not delete your Supabase database**.
2. Download `GramOS_v3.8_Complete_Node.zip` into `~/Downloads`.
3. Extract into a **fresh folder**:

```bash
cd ~/Downloads
mkdir -p gramos-v3.8-full
unzip -o GramOS_v3.8_Complete_Node.zip -d gramos-v3.8-full
cd gramos-v3.8-full
npm test
PORT=8001 npm run dev
```

4. Open `http://localhost:8001/demo`, `http://localhost:8001/admin/login`, and `http://localhost:8001/v/shirpur/contact` (the last requires your Supabase connection).

If you have a **working and unmodified v3.7** folder and want only the changed code:

```bash
cd ~/Downloads/gramos-shamvadi-v2
unzip -o ~/Downloads/GramOS_v3.8_Changed_Files_Only.zip -d .
npm test
npm run dev
```

Do not apply the changed-files archive to v2.9 or v3.0 — it assumes v3.7.

## Upload PDFs through Admin

1. Sign in at `/admin/login` using the Supabase Auth account with platform admin or village editor permissions.
2. Choose the correct village. For meeting notices, financial reports, RTI or resolutions, open **Notice board** and create or edit an item. Choose its category, type its Marathi/English title, and upload a PDF.
3. For Lokseva application forms, open **Lokseva — Forms and Downloads**; for a service card, open **Lokseva**. Select a PDF (max 5 MB). The PDF uploader populates the **External link** field.
4. Set the item to **Published**, click Save, then open the public page. The PDF download link will appear. A blank/unpublished item does not show a misleading download button.
5. PDFs in `service-documents` are **public**. Upload only approved government forms/notices; never upload private complaints, ID documents or personal data.

Existing bucket configuration has been verified in the active `gramos-clean` Supabase project: `service-documents` (public, PDF-only, 5 MB limit) with authenticated editor upload policy, and village content tables protected by RLS. No v3.8 SQL migration needed. This does **not** test a live authenticated upload from your Safari browser: test one PDF after deploying.

## Contact details and footer logo

`Admin → Village Settings`: enter **Address (Marathi/English)**, **Phone**, **Email**, **Office hours**, and optionally the **Page-bottom logo**. Click Save Village Settings. The Contact page also offers separate page headings and Google Maps link fields in its own admin editor. Do not use fake office addresses.

## Hosting / deploying

This application supports Vercel. In the new complete project folder, link to your **existing** project and deploy a test preview first:

```bash
vercel login
vercel link
vercel deploy
```

After checking `/demo`, `/admin/login`, `/v/shirpur/contact`, uploaded PDFs, published village content and the sitemap, publish using `vercel deploy --prod`.

Keep all real secrets in Vercel environment variables, not `config.js`: `SUPABASE_SERVICE_ROLE_KEY`, `TURNSTILE_SECRET_KEY` and `SITE_URL` if used by your backend. `config.js` must contain only **public** values. The visitor complaint form requires Cloudflare Turnstile setup separately.
