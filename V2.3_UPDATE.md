# GramOS v2.3 – existing Node.js project update

## What changed
- No separate public-page codebase: /demo/about and /v/{slug}/about call the SAME renderer, HTML classes, footer and header.
- Real villages without published facilities preserve four editable placeholder positions rather than collapsing the layout; placeholders are not invented village facts.
- Citizen-services cards and the video-gallery panel share the exact same parent columns as the photo-gallery/notice-board section. Negative margins were removed; headings are top-aligned; cards cannot overlap the video panel.
- Demo and live villages share the same navy four-column footer layout. Public government portal links display as editable defaults if none have been entered for a village.
- The About editor links directly to editable facts, profiles, committees, facilities, duties and custom blocks. Existing saved data and role protection are untouched.

## Mac update
Stop the old node server, then extract the zip into the existing folder:

```bash
cd ~/Downloads
unzip -o GramOS_v2.3_Node.zip -d gramos-shamvadi-v2
cd gramos-shamvadi-v2
npm test
npm run dev
```

Open /demo/about and /v/shirpur/about. The live village will not display fictitious demo officials or photographs. To make the content match, publish actual village records from /admin/login -> Village -> About page.

## Database
No SQL migration is required in this version: v2.2 already supports all editable field types. Do not run 01_setup.sql again. No database tables were deleted or changed.

## Note
The CSS is tied to one single HTML template, but a demo populated with sample content and a real village with no records naturally cannot show identical names, images, or text. Empty-state boxes now retain the same geometry.
