# GramOS v4.3 — Village-wide logos, cleaner navbar editor, visible removal option

**Applies to:** Existing GramOS **v4.2 Node.js/vanilla-JS** project, backed by the **`gramos-clean`** Supabase project (`public.villages`, `public.village_members`, `public.village_site_drafts`). Do not install in the *older Next.js / `gramos-platform`* repository or apply its SQL migrations here.

## What's new

1. **Navbar logo editor:** Admin → choose a village → **Navbar logo**. Choose a separate header image or leave the URL empty to reuse the village primary logo, upload PNG/JPG/WebP, set width (40/52/64/72/84px), contain/cover, rounded/square/circle, and image position. Values are validated; mobile width is capped.
2. **Village-only footer:** Admin → village → **Footer & bottom logos**. Up to 12 images, their order, social links, useful links, and office hours are stored in that **village's** `villages.site_settings`. They appear on every page of **that village**. Changing Village A's footer never changes Village B. The former platform-wide `/admin/branding` page is retired and `gramos_platform_branding` no longer overrides public village data. Its table remains intact for rollback.
3. **Visible Remove website:** Super Admin dashboard shows **Remove website** next to each village. Enter the village slug to confirm archive. Archives make a village non-public without deleting its content. The button becomes **Restore**, which returns it as an unpublished draft. Admins/reviewers cannot archive; database trigger from v4.2 enforces the role.
4. **Drafts:** Navbar and footer forms now offer **Save draft** or **Publish**. Drafts remain private until released from Overview. Existing Homepage and Village Information draft workflows continue unchanged.
5. **No design/template replacement:** Existing pages, shared ticker *within* each village, animations, read-more public dialogs, admin page groups, footer legal imprint, permissions, and data remain.

## Database changes

**No SQL migration or database writes are required for v4.3.** All new preferences use the existing JSONB `public.villages.site_settings`. The already-installed v4.2 tables/functions `village_site_drafts` and `gramos_save_site_draft`, `gramos_publish_site_draft`, and `gramos_guard_archive_v42` remain necessary. A v4.3 patch **does not create or transfer user accounts, modify live villages, or change storage files**.

Do not delete the existing `gramos_platform_branding` table until after a verified rollback window. It is now deliberately ignored by the public app.

## Install onto your existing v4.2 Git checkout

Back up the repo, Supabase database, and Storage first. Work in a new branch:

```bash
cd /PATH/TO/YOUR/EXISTING/GRAMOS-REPO
git switch -c gramos-v43-village-branding
unzip -o ~/Downloads/GramOS_v4.3_Changed_Files_Only.zip -d .
npm test
node tests/v40-snapshots.mjs
python3 tests/v40-browser-static.py  # optional, requires Playwright + Chromium
npm run dev
```

Open the URL printed by your server (normally `http://localhost:8000`). Navigate to `/admin`, sign in as the existing Super Admin, select a village, and check the new Navbar logo page.

Do not replace `config.js` with credentials from another Supabase project. The patch doesn't include service-role credentials.

The hardcoded © 2026 company copyright remains uneditable. **Do not decide new permanent template text or locked fields until you provide the exact copy and list of locked sections.**

## Transfer entire Supabase project to another account

Use **Supabase Project Transfer**, not a SQL copy, when you need to hand over the whole project and retain Auth, Storage, keys and functions.

1. Ask the new owner to create a Supabase organization, then invite you to it with an organization-level role; accept.
2. Your account must be an Owner of the source organization. Open `https://supabase.com/dashboard/project/nttnrfyidokwnkqrukdb/settings/general`, find **Transfer project**, and select the destination organization.
3. Review billing and blockers (GitHub/Vercel integrations, add-ons, target-plan limits). Make a backup before confirming. Complete the transfer in Supabase Dashboard.
4. Check the new owner has access, existing data/Auth/Storage and apps work, then leave their organization if you no longer need access. **The transfer transfers EVERY village in `gramos-clean`, not just one village.**
5. GitHub and Vercel ownership are separate; transferring Supabase does not transfer the repository/domain/deployment projects.

Official docs: https://supabase.com/docs/guides/platform/project-transfer and https://supabase.com/docs/guides/platform/project-transfer/transfer-ownership

**If you only want a copy** or need to hand over **one village only**, do NOT transfer this shared multi-village project. Create a separate Supabase project and plan a scoped migration of that village's rows, media, access policies, and user accounts.
