# GramOS v4.2 — Clean Admin, Role Hierarchy, Website Drafts & Shared Footer

**21 November 2026. Install on the GramOS v4.1 Node.js/vanilla JavaScript project, not on the old Next.js `apps/gramos` project.**

## What changed

1. A separate admin Home editor at `/admin/villages/{id}/home`; village information remains separate.
2. One Overview for every village, including an inline large website preview, draft status and publishing controls. The main admin dashboard also previews a selected village without opening another page.
3. Clear grouped, collapsible navigation for information, services/schemes and news/progress pages. Records and photos are behind a per-page **Manage this page's photos & records** disclosure.
4. A global Super Admin screen `/admin/branding` for up to **12 shared bottom logos** and shared social links, useful links and office hours. Changes affect all villages' public pages. Existing per-village data is preserved, and shared branding does not override legacy settings until the first explicit global Save.
5. Three permission levels, enforced by existing Supabase RLS and new auth-checked RPCs:
   - **Super Admin**: stored in `platform_admins`, can create villages, archive/restore villages, manage staff accounts, grant Super Admin to an existing Auth user, and edit platform-wide branding.
   - **Admin**: village member with `editor`/legacy `owner` role, can edit/publish their assigned village and read its complaints, **cannot create/archive villages, grant staff/roles or global branding**.
   - **User — Complaint Viewer**: village member `reviewer`, **read-only complaints for assigned villages**; no public website editing.
6. **Save draft** and **Save & publish now** for Home and Village Information. The former stores edits in `village_site_drafts` without changing the published site. Overview contains **Publish saved changes**, **Discard draft**, and **Publish/Unpublish website**. Content records retain their pre-existing draft/published workflow. Published/unpublished village state is a distinct operation from saving a draft.
7. A **Read more** button opens an accessible native dialog on the **public website** for long card descriptions, preventing stretched cards. The admin editor itself is not converted into those dialogs.
8. Larger previews and consistent responsive font sizing and overflow protections. The fixed 2026 company copyright/phone lines and single per-village scrolling announcement from v4.1 remain unchanged.

## Install the files (Mac)

Back up your existing Git repo and database/Storage before deploying.

**Option A — complete project:** unzip `GramOS_v4.2_Complete_Node.zip` into a clean folder. Copy it into the current *Node* GramOS repository after reviewing changes. Do not delete the repository's `.git` directory.

**Option B — changed files (only when the installed code is exactly v4.1):**

```bash
cd /path/to/YOUR/gramos-repository
unzip -o ~/Downloads/GramOS_v4.2_Changed_Files_Only.zip -d .
node --version
npm test
npm run dev
```

Open `http://localhost:8000/admin`, authenticate, select a village and use **Overview** → **Edit homepage**. Test **Save draft**; ensure the live public site is unchanged, while `/v/{slug}?preview=1` as an authorized editor reflects your draft. Use **Publish saved changes** on Overview, refresh the public page and verify it now matches.

For Vercel: keep the **same GitHub repository / Vercel project** that currently serves the Node v4.1 website. In that repository review `git diff --stat`, commit, push to a staging branch and deploy a Preview first; promote only after browser testing. Do not deploy the old Next.js-domain patch into this Node website.

## Super Admin and user setup

The existing Super Admin account remains the only current Super Admin. `/admin/users` can grant Super Admin to **an account that already exists in Supabase Authentication → Users**. To create or invite a new Auth user, use the **Supabase Auth dashboard** first, then assign their Auth UUID as Admin or Complaint Viewer under the village **Users & access** screen (Super Admin only). Normal Admins cannot access that screen or grant roles. No service-role secret is exposed to browser JavaScript.

**Removing a village** is implemented as **archive** for safety, preserving its records and allowing a Super Admin to restore it. It is not irreversible deletion.
