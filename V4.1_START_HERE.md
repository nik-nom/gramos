# GramOS v4.1 — fixed company footer and simpler connected admin

**Install this only on the GramOS v4.0 Node.js/vanilla JavaScript source.** This is the SAME website and the SAME existing `gramos-clean` Supabase project. It is **not** a Next.js update. Do not combine it with any older GramOS Next.js/`gramos-platform` custom-domain patch or SQL migration.

## What changed — no other village content was replaced

1. **Bottom logo strip:** It displays only actual bottom logos configured for that village (up to 12), in responsive, non-stretched cells. Without an uploaded bottom logo, no unrelated village name or sample mark appears there. Existing single `footer_logo_url` remains supported. The *main village header logo* and legitimate village names remain unchanged.
2. **Fixed company imprint on every public page, in both languages:** `Copyright © 2026 · Swaraj Gram Soft and Software Private Limited™ · Jalna · 9923227879 / 9423227879`. This is application code, not editable village data. Old village copyright/credit fields are retained in the database but ignored by the public footer. The editor shows the fixed notice read-only.
3. **Marathi social media:** Public Contact and footer use the Marathi label `समाजमाध्यमे`. English pages keep their English heading; existing social URLs still work. The public layout and other contact content are untouched.
4. **One scrolling announcement for all pages of one village:** Edit **Admin → Village → Home page → Scrolling message** once and save. The public header on Home, About, Contact, Schemes, News, and other routes reads the same village-level `site_settings.quote_mr` / `quote_en` values. Another village maintains its own message.
5. **Simpler admin:** Open **Workspace overview** for clearly labeled links to each editor, website status, uploaded-logo count, and current announcement. Less-used page controls are organized under a collapsible group; all previous editors remain. Home and Footer have larger previews and a **Refresh preview** button.
6. **Important save fix:** Existing v4.0's form dispatcher omitted `homeForm` and `footerForm`; both now dispatch to the existing Supabase save handler. Edits and uploaded logos show an unsaved-changes reminder until saved.

## Installation — use the existing repository and Vercel projects

1. Back up the existing GitHub checkout and existing custom `config.js` / environment settings. Keep your current Vercel deployment unchanged until the tests below pass.
2. If your existing repo is **exactly v4.0**, extract `GramOS_v4.1_Changed_Files_Only.zip` into the **root** of that repo, replacing matching files. If you are unsure what release your repo contains, first extract `GramOS_v4.1_Complete_Node.zip` into a separate folder and compare, rather than overlaying an unknown version.
3. In the project root run:

   ```bash
   npm test
   npm run dev
   ```

4. Open `http://localhost:8000/admin/login`. Sign in, pick a real village, then visit **Workspace overview → Home page**. Edit the Marathi scrolling message, click **Save homepage**, refresh and check all pages of that village show it.
5. Visit **Workspace overview → Logos & footer**. Upload an image for each desired bottom-logo row, click **Save logos & footer**, then refresh the public preview. Test adding, removing, reordering and replacing 12 logos; never rely on an upload alone without the Save action. This is distinct from **Village information → Main village logo**.
6. Check Marathi Contact and page footer, check the fixed © 2026 legal line with both phone numbers, and test a second village for isolation. Confirm no prepopulated unrelated village logo or name appears in the bottom-logo strip.
7. Push a tested commit to your **existing** GitHub repository/branch only after successful staging checks:

   ```bash
   git status --short
   git add -A
   git commit -m "GramOS v4.1: fixed platform footer and clearer admin"
   git push origin main
   ```

   Adjust `main` to the branch currently deployed by your Vercel project. Confirm Vercel deployment becomes Ready and inspect `/admin/login` and real public village pages. Do not repoint Vercel to the older Next.js source or swap Supabase projects.

## Security

Never put the Supabase `service_role` key into `config.js`, browser code or a `NEXT_PUBLIC_` variable. The existing publishable key is intended for browsers, with village-specific row-level security enforcing permissions. Do not remove RLS to fix a failed save; first confirm the editor account and authorization for that specific village.
