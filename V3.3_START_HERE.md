# GramOS v3.3 — Automatic Supabase Sitemap, Google SEO & Deployment

This is an update to your **existing GramOS v3.2** website, not a separate app. It preserves all existing public layouts, editable pages, animations, admin screens and Supabase records.

## What is new

- `/sitemap.xml`: generated **live from existing Supabase tables**, not manually uploaded. Includes published villages and their eligible site pages, plus published news article URLs. Draft, archived, demo, missing and per-page noindex routes are omitted.
- `/robots.txt`: references the sitemap automatically, and lists the sitemap; admin and demo pages use a noindex meta tag, while internal API paths are disallowed.
- Server-delivered HTML metadata for ` /v/:slug`, ` /v/:slug/:page`, and `/v/:slug/news/:article`: village-aware title, description, canonical URL, robots, Open Graph and Twitter tags. New articles use their *own* article headline; per-page admin SEO overrides apply where appropriate.
- Browser titles default to the **same editable Marathi heading** shown on the corresponding public page. Separate SEO title, description, sharing image and noindex still work via Admin → Village → SEO & Metadata.
- The SEO admin screen links directly to the sitemap and robots endpoints.
- Preserves logo-free `Loading…`, the moving blue ticker, on-scroll section reveals, carousel behavior and reduced-motion safeguards.

## Files and installation

Use `GramOS_v3.3_Changed_Files_Only.zip` to update an **existing v3.2 repository**, unpacking its `src/`, `api/`, `tests/`, `database/` files directly into the project folder. Do not put the changed files into a nested GramOS folder. Back up your project first.

Or start with `GramOS_v3.3_Complete_Node.zip`, which contains the complete codebase. Both packages intentionally contain **no private Supabase service-role key**.

## Set production environment variables in Vercel

Required for public SEO endpoints:

- `SUPABASE_URL` = your Supabase project URL
- `SUPABASE_PUBLISHABLE_KEY` = the publishable key shown in Supabase Project → Settings → API Keys. Never use the service-role key here.
- `SITE_URL` = the *real production origin*, e.g. `https://your-domain.in` (no trailing slash, no `/v`).

Previously configured visitor-form services also require their existing server secrets:

- `SUPABASE_SERVICE_ROLE_KEY` (server only, never in `config.js`)
- `TURNSTILE_SECRET_KEY` (server only)

The public browser `config.js` retains its existing Supabase URL and publishable key. Do not replace it with server secrets.

## Quick commands on your Mac

In Terminal inside your actual repository folder:

```bash
npm test
npm run dev
```

Open `http://localhost:8000/demo`, `http://localhost:8000/admin/login`, `http://localhost:8000/sitemap.xml` and `http://localhost:8000/robots.txt`. For the sitemap to work in local development, you need network access to your Supabase project.

Deploy to the **same existing Vercel project**:

```bash
npm install -g vercel
vercel login
vercel link
vercel env add SUPABASE_URL production
vercel env add SUPABASE_PUBLISHABLE_KEY production
vercel env add SITE_URL production
vercel deploy --prod
```

When prompted, select your existing Vercel project. The last three commands prompt for the variable values; configure missing `SUPABASE_SERVICE_ROLE_KEY` and `TURNSTILE_SECRET_KEY` similarly if you need the visitor submission features.

If your Vercel project is already linked to GitHub, instead commit and push the update to your production branch; Vercel can redeploy from that branch:

```bash
git add .
git commit -m "GramOS v3.3 dynamic Supabase sitemap and server-rendered SEO"
git push origin main
```

Use the right branch if your repository uses a different production branch.

## Validate after deployment

```bash
curl -i https://YOUR-LIVE-DOMAIN/sitemap.xml
curl -i https://YOUR-LIVE-DOMAIN/robots.txt
curl -s https://YOUR-LIVE-DOMAIN/v/shirpur/services | grep -E '<title>|canonical|name="robots"'
```

Replace the domain. For every published village, inspect **the real HTML response** as well as browser page text. Add the URL `/sitemap.xml` once in Google Search Console. Google may take time to crawl and index pages, and indexing is not guaranteed.

## Database compatibility and checks

**No SQL migration is needed.** The existing `public.villages` fields `slug`, `status`, `site_settings` (JSONB) and `updated_at`, plus `public.content_items` for published news, already supply everything. This update does not insert, delete or publish database rows. The current connected `gramos-clean` Supabase project was checked on 2026-11-21: 1 published village (`shirpur`), 0 published news, 1 platform-admin role. A public `anon`-role read of the published village succeeded.

Do not reset Supabase or run `database/01_setup.sql` again just for this SEO upgrade.

## Verification boundaries

`npm test` tests existing page/admin contracts and the new sitemap/metadata handlers with a simulated public Supabase response. Actual editor login, editing/publishing through your own browser, Vercel deployment and browser animations should still be checked on the live domain. This environment cannot perform your Vercel login or deploy into your account. In this environment direct network requests from the local Node runtime to Supabase were blocked, so the local sitemap returned HTTP 503; the connected database itself was inspected through Supabase separately.
