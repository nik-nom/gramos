# GramOS v4.7.2 — Reference footer, village facilities, uploaded forms

This update builds on **GramOS v4.7.1 with separate Vercel projects**. It does not change your database schema, site copy, village data, admin roles, village logo settings, public routes, or the platform-owned V Swaraj © 2026 text.

## Changes

1. The **ग्राम पायाभूत सुविधा** area always has the same four standard labels, in order:
   - ग्रामपंचायतीची लोकसंख्या
   - एकूण कुटुंब संख्या
   - जॉबकार्ड धारक कुटुंब संख्या
   - बसविण्यात आलेले CCTV

   With no *published data for the current village*, the value reads **No Data**. An administrator can create an `about_facilities` published content item for a specific village using an exact label or one of the keys `population`, `households`, `job-card-households`, `cctv`; its `details.value` or the record's body becomes the metric. Extra facility cards remain supported. **No other village's data is ever copied.**

2. The public footer's **spacing and typography** follow the reference. Its existing headings, links, contact details and fixed legal notice **are not rewritten**. The screenshot showed an older third-party footer imprint; this update intentionally preserves **V Swaraj Gramsoft and Software Private Limited™, Jalna, Copyright © 2026** as explicitly required in earlier specifications. The font family is still **Mukta**, including the admin unaffected by public CSS changes.

3. Two user-uploaded Right to Service PDF files are copied **byte-for-byte unchanged** into `assets/forms/`, `apps/public/assets/forms/`, and `apps/admin/assets/forms/`:
   - `/assets/forms/V_Swaraj_Gramsoft_Right_to_Service_Form_1.pdf`
   - `/assets/forms/V_Swaraj_Gramsoft_Right_to_Service_Form_2.pdf`

   The existing three V Swaraj form downloads are unchanged. An unobtrusive **इतर PDF प्रती** dropdown under the existing **लोकसेवा अर्ज** download exposes both uploaded copies without creating duplicate service cards.

## Install on client's existing GitHub repository

**For the changed-files ZIP** (starting from v4.7.1):

```bash
cd ~/Downloads/gramos
# If the repository is in a different directory, cd into that directory instead.
git status
git pull --ff-only origin main
unzip -o ~/Downloads/GramOS_v4.7.2_Changed_Files_Only.zip -d .
node scripts/sync-vercel-projects.mjs
node scripts/check-vercel-projects.mjs
npm test
node tests/v472-facilities-footer-pdfs.mjs
git status --short
# Review the changes, ensure no .env/private keys are staged.
git add src/about.js src/services.js src/services-reference.js styles.css index.html package.json scripts/sync-vercel-projects.mjs assets/forms apps/public apps/admin tests/v472-facilities-footer-pdfs.mjs tests/v472-static-demo.mjs V4.7.2_START_HERE.md
git commit -m "GramOS v4.7.2 footer, infrastructure stats and original PDFs"
git push origin main
```

If the client Hobby Vercel project blocks a Git commit because of **commit-author access**, make the commit using the GitHub identity actually linked to the Vercel project owner. Simply changing the Git author name is not a substitute for genuine GitHub authorization. Make a backup/branch first if your repo contains other work.
