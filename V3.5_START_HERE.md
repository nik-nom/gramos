# GramOS v3.5 — Village logos, beneficiary lists, Excel and Yojana

## Install on your existing project (recommended)

1. Download `GramOS_v3.5_Changed_Files_Only.zip` from this chat into Downloads.
2. Stop your running local Node.js server with Control+C.
3. In Terminal:

```bash
cd ~/Downloads/gramos-shamvadi-v2
unzip -o ~/Downloads/GramOS_v3.5_Changed_Files_Only.zip -d .
npm test
npm run dev
```

Open `http://localhost:8000/demo/beneficiaries` for sample cards, or `http://localhost:8000/v/shirpur/beneficiaries` for published records of the village.

## Village logo upload

In Admin, sign in and select the village > Village Settings. Use **Upload village logo** (.png/.jpg/.webp), inspect its preview, then **Save** Village Settings. The saved logo is reused in header, footer, and page favicon across the village's public pages. Each village has its own logo. If no image is uploaded, the fallback image remains. The old logo is not immediately deleted from storage; admin may manually clean up stale media as needed.

## Beneficiary lists & Excel

Select Admin > Village > **Beneficiary Lists — Excel Upload** (or `लाभार्थी यादी — Excel`). Click **Add new item** or **+ New**.

1. Enter the scheme/list title in Marathi (and optionally English), and an optional description.
2. Choose individual or public-benefit scheme category.
3. Upload a genuine `.xlsx` file, up to **5 MB**. Other Excel types (`.xls`, `.xlsm`) are not accepted. The private object path fills automatically.
4. **Remove Aadhaar numbers, bank/account details, phone numbers, personal contact details, IDs, and any non-public personal data before publishing**. Excel files may contain hidden worksheets, comments, and metadata. Review those too. The server cannot determine whether a list contains sensitive information.
5. If the workbook is suitable for publishing, tick the approval checkbox for public download. Save and explicitly publish the item. A link appears only after **both** approval and publication. Without these, the card shows “List not yet available”.
6. The browser downloads the existing XLSX file through a short-lived signed link. This feature **does not import individual spreadsheet rows into the database**. Every list is one content item with an Excel attachment.

Use `examples/GramOS_Beneficiary_Excel_Sample.xlsx` as an example structure; it contains only dummy data. Public real data must respect relevant Indian data protection requirements and local government policies.

## Other Yojana

Admin > Village > Government Schemes — Records: add schemes and publish them. Published schemes automatically appear under **Other Government Schemes** on the beneficiary page and on the separate `/schemes` page. The public cards are data-driven, not permanently hardcoded.

## Production deployment (same existing Vercel project)

Run from the repository root, after you have installed the v3.5 update and committed your changes:

```bash
npm test
npm install -g vercel  # Only if the CLI is not installed
vercel login            # Only if you are not already logged in
vercel link             # Select your existing GramOS Vercel project
vercel deploy           # Test the preview first
vercel deploy --prod    # Publish after checking it
```

Existing project environment variables required by this app:
- `SUPABASE_URL` — Supabase project URL.
- `SUPABASE_PUBLISHABLE_KEY` — Supabase publishable API key.
- `SUPABASE_SERVICE_ROLE_KEY` — **server-only** Supabase secret required for short-lived public list downloads, keep out of client files.
- `SITE_URL` — canonical production origin.
- `TURNSTILE_SECRET_KEY` — configured separately if using the citizen submission form.

The `beneficiary-files` private bucket and `beneficiary_lists` content kind were added **already** in the connected `gramos-clean` Supabase project. **Do not rerun the database migration there.** For another Supabase project, run the included `database/13_v35_beneficiary_workbooks.sql` using the approved migration workflow, only after verifying its compatibility with that project's schema.

## Verification / important limitations

- Node.js automated tests passed and desktop/mobile static browser rendering was checked.
- The Excel upload validator and signed-download access rules were exercised with mocks and a genuine sample XLSX. End-to-end authenticated uploading, published production downloads, Safari rendering, and Vercel integration **still need to be tested** with actual credentials.
- Excel attachments reside in a private Supabase storage bucket. Approved, published files are intentionally accessible via a short-lived, publicly requestable signed download link. **Never publish private beneficiaries' data.**
- The security advisor still reports a pre-existing leaked-password-protection setting disabled in Supabase Auth. Enable it in your project settings.
- The orange `sawrgoan.vercel.app` site in your reference screenshots may be a *different repository* from GramOS. This ZIP changes the current blue GramOS codebase, not that deployment by itself. To update `sawrgoan.vercel.app`, deploy this code only if it is actually its linked source project; otherwise update the correct repository separately.
- Code updates do not automatically deploy to GitHub/Vercel. After preview testing, commit, push and deploy to the right project.
