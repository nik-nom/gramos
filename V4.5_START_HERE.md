# GramOS v4.5 — Lokseva / Citizen Services screenshot update

**Based on the supplied 21 November Shamvadi screenshots and three original V Swaraj Gramsoft PDFs.**
This is a **code-only upgrade of GramOS v4.4 Node.js**, not the older Next.js app. No Supabase database migration or record update is required.

## Changes

- `/demo/services` and `/v/{village}/services` now share the reference-style Lokseva layout: six tabs (All, Services, Application Steps, Download Forms, Citizen Links, Tax Payment QR).
- Seven default Marathi service cards, three application steps, three genuine downloadable PDFs, and ten colored citizen links appear automatically for a new or existing village, even if no Lokseva rows were added in Supabase.
- Bundled original forms: `assets/forms/V_Swaraj_Gramsoft_Form_1.pdf` (7 pages), `...Form_2.pdf` (1 page), `...Form_3.pdf` (12 pages). They are **byte-for-byte identical** to the three supplied source files. They retain their original wording, legal text, organization credits, and page design.
- A village's own *published* content item overrides a default card **only when it uses the same `kind` and `slug`**. New slugs append additional cards. Unpublished edits do not affect public pages, and a private preview can show drafts.
- The admin has a collapsed **Built-in cards — optional customization** menu. Click a default card to prefill a new village-specific record. Save as draft or publish using the existing content workflow. This never changes the template for other villages.
- The **Tax Payment QR** tab is deliberately empty until a verified QR image is uploaded for that village in Admin → Citizen Services. The original PNG/JPG/WebP is uploaded uncompressed so it remains scannable. It is never shared across villages. No sample/fictional payment QR is generated.
- Services cards now use a three-column desktop grid, olive outlines, dark red headings, natural text height, no nested scrolling, and responsive two-column/mobile layouts. The downloadable forms use blue pill buttons. Citizen links use the pastel palette in the screenshots.
- Other public pages, About text, existing PDFs, navbar/footer, village content, auth, and permissions were not redesigned.

## Install on your Mac

1. **Back up the existing v4.4 repository and production deployment first.** Do not mix this package with the separate Next.js/domain-management patch.
2. For the changed-files update, extract `GramOS_v4.5_Changed_Files_Only.zip` into the **root of your existing GramOS v4.4 Node.js repository**, replacing matching paths. The 3 PDFs must be copied too.
3. In Terminal, run:

```bash
cd /path/to/YOUR-GRAMOS-REPOSITORY
npm test
npm run dev
```

4. Open `http://localhost:8000/demo/services` and click all six tabs. Open `http://localhost:8000/assets/forms/V_Swaraj_Gramsoft_Form_1.pdf`, Form_2.pdf, and Form_3.pdf. Each must load and download.
5. Test a real village at `http://localhost:8000/v/YOUR-VILLAGE-SLUG/services` and log into the existing admin. Use **Village → Citizen Services → Built-in cards → Customize**. Save a draft, verify it appears only in a signed-in private preview, then publish it and verify only that village changes.
6. Inspect on desktop and mobile, verify no text overflow, test one form download, and verify the QR image if one has been approved and uploaded.
7. Deploy to a **Vercel preview deployment** from the same repository; test all steps again before promoting to production.

## No database migration

This upgrade does **not** create tables or change RLS. It uses your existing `gramos-clean` Supabase tables: `villages`, `content_items` and per-village `site_settings`. Admin forms already save those records. The PDF files are shipped as public static assets and **do not need to be uploaded to a Supabase bucket**. The SQL migrations from the earlier Next.js `gramos-platform` project are incompatible and must not be run here.

## Important about content

The visible Marathi service descriptions, fees, time windows and citizen links were used as the supplied **template reference**. Local government requirements or websites can change; check them with the relevant Gram Panchayat before relying on them as official instructions. The code deliberately does not create citizen applications, registrations, or online payments; these are information/download links. The QR tab is not a payment gateway.

Re-deploy the previous **v4.4** source code. No database rollback is necessary because this release does not modify the database. Any new village-specific content records created by admins remain in Supabase and can be edited or unpublished separately.
