# GramOS v2.1 — clean About All Information (existing Node.js project)

This is a **replacement of project source files**, not a new project. It uses the existing `gramos-clean` Supabase database, administrator account, and the same Shamvadi-style site template. **Do not execute earlier database SQL setup scripts again.**

## Changes

1. Removed the oversized two-column "More About the Village / ग्रामपंचायतीची अधिक माहिती" outer box and narrow inner card from **About → All Information**. Additional information (when saved and published through Admin) is displayed as normal, full-width headings and text instead of boxes.
2. Removed the extra-information sample photograph and the History image from All Information. This is a *presentation* change; existing image URLs in Supabase are not deleted.
3. Removed the old sample extra-information item from `/demo/about` so demo does not show a placeholder box/photo.
4. Preserved six About tabs, editable database-driven content, office bearer/staff portraits, community committees, facilities, colored roles cards, blue navigation and footer.
5. Both `/demo/about` and `/v/{village}/about` run through the **same** `renderAboutPage` module. The demo uses labelled example records; the actual village uses only its Supabase records. Real-village pages will not show invented sample data.
6. The Admin still provides **About → Additional Sections** to edit text. The legacy cover-image setting is labelled as not displayed on All Information.

## Update on Mac

Stop the old development server with `Ctrl+C`, then download the new ZIP into Downloads and execute:

```bash
cd ~/Downloads
unzip -o GramOS_v2.1_Node.zip -d gramos-shamvadi-v2
cd gramos-shamvadi-v2
npm run dev
```

Open:

- Demo About: http://localhost:8000/demo/about
- Your village About: http://localhost:8000/v/shirpur/about
- Admin: http://localhost:8000/admin/login

In Safari use `Command+Shift+R` once to clear the cached CSS. For a fresh content update, edit and **publish** through the admin; the public village only shows published records.

## GitHub/Vercel

Upload the **contents** of the extracted folder to the existing GitHub repo root, keeping `src`, `assets`, `api`, `database` and `tests` separate. Your current Vercel project can redeploy from that repo. No new repository, Supabase project, domain or SQL migration is needed.

## Checks

Run `npm test` in the folder. Includes a regression test confirming the old boxed layout and photos have been removed from All Information, and that demo and village routes share the same template. Automated tests do not guarantee exact Safari rendering.
