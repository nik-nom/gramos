# GramOS v3.2 — Exact Marathi Titles, SEO Editor, Simple Loading

This updates the **existing** GramOS v3.1 Node.js / Supabase / Vercel codebase; do not create a new project or repository.

## Changes
- Uses reference-style Marathi page titles. The homepage browser title defaults to `ग्रामपंचायत {गावाचे नाव}`; inner pages default to e.g. `नोटीस बोर्ड | ग्रामपंचायत {गावाचे नाव}`. Each village automatically uses its own name, not Shamvadi's. Existing page heading editors still control the titles *shown within* the page.
- Loading page now says **Loading…** only. There is no GramOS logo, village logo, heading, or tagline in the loading state.
- Admin has a new **SEO आणि मेटाडेटा / SEO & Metadata** entry. Pick any of 13 pages, and edit its browser title, meta description, keywords, HTTPS sharing image, and indexing preference. Metadata can be edited separately for each village and page; an image upload picker is included.
- Public page navigation updates browser title, description, canonical, Open Graph, Twitter card, and robots tags. Draft villages and admin previews are noindex.
- Multiple village sites, their publication statuses, content records, sections, and admin login behavior are unchanged. No database reset, SQL migration, or new Supabase project required.

## Exact install
1. Make a copy of your current project. Unzip **GramOS_v3.2_Changed_Files_Only.zip** into the existing GramOS project folder, where `package.json`, `src/`, `styles.css` live. Let changed files replace existing ones. Do **not** replace or remove `config.js`, `.env`, stored uploads or Supabase credentials.
2. From that folder run:

```bash
npm test
npm run dev
```

3. Open `/admin`, select a village, click **SEO आणि मेटाडेटा**, select a page and save metadata. Then test `/v/<village-slug>` and `/v/<village-slug>/notices` etc.
4. Test by editing a village-specific title in admin, saving, refreshing its live page, and checking the browser tab and page source in developer tools. Public **body text** (H1, nav, cards) is edited in page editors / Village Settings, not in SEO.

## Important deploy and SEO notes
This downloadable package has **not** automatically modified your Mac's local Git checkout, GitHub or Vercel deployment. After merging into the existing repo, run:

```bash
git status
git add index.html src/main.js src/public.js src/admin.js src/seo.js styles.css package.json tests/v32-seo-multi-village.mjs V3.2_START_HERE.md
git commit -m "GramOS v3.2 SEO metadata and simple loading"
git push origin main
```

The current Node.js/Vercel site is a **client-rendered SPA**. Dynamic metadata changes the DOM after JavaScript loads and works for browsers and some social/search crawlers, but is **not a guarantee of Google or social-media SEO indexing**. For reliable crawler metadata, add server rendering or static prerendering in a later upgrade. The project supports per-page values now without an additional database migration.

## Database details / verified state
- The connected `gramos-clean` project holds `villages.site_settings` as JSONB. This upgrade stores `site_settings.seo.<page>` in the village's existing row; updates still use established RLS and the existing save/publish workflow.
- As inspected on November 21, 2026, the connected database contains one published `shirpur` record and zero published content items, not a fully filled Shamvadi copy. No village content was edited, deleted or published by this package.
- Two village sites are independent by their unique slug and id. The bundled tests verify defaults and route metadata isolation; they cannot substitute for a real authorized admin save in your production browser.
