# GramOS v3.6 — Yojana beneficiary subpage + editable footer logo

This is a **small update** to the existing blue Shamvadi-style GramOS Node.js project; it does **not** update the unrelated orange `sawrgoan.vercel.app` project unless you deploy the same repository there.

## Install only changed files

1. Download **GramOS_v3.6_Changed_Files_Only.zip** to your Mac's `~/Downloads` folder.
2. Stop the currently running Node server (Ctrl+C).
3. Run:

```bash
cd ~/Downloads/gramos-shamvadi-v2
unzip -o ~/Downloads/GramOS_v3.6_Changed_Files_Only.zip -d .
npm test
npm run dev
```

Open the test pages:

- `http://localhost:8000/demo/schemes` — Yojana page, now with the **लाभार्थी यादी** fourth entry.
- `http://localhost:8000/demo/beneficiaries` — the actual Yojana beneficiary *subpage*, in the same page style and same Yojana navigation.
- `http://localhost:8000/v/shirpur/schemes` — published schemes for Shirpur only.
- `http://localhost:8000/v/shirpur/beneficiaries` — published beneficiary records for Shirpur only.

The legacy beneficiary URL is preserved for links, bookmarks, and SEO. The separate *top-level navbar* entry is removed; visitors now open the beneficiary page through **योजना → लाभार्थी यादी**. The footer links to the same subpage as a nested Yojana link. Empty real villages display a safe empty state instead of copying demo lists.

## Admin: Add Excel beneficiary lists within Yojana

1. Sign in at `/admin/login`; choose your village.
2. Open **Government Schemes — Full Page** (Yojana).
3. Under **Yojana → Beneficiary Lists — Upload Excel**, select the new item editor, click **+ New**, add title/description, and upload the `.xlsx` file.
4. Verify the file does not contain private personal data. If you intend public download, approve it and **Publish**.
5. Edit headings and the fourth Yojana tab label in **Government Schemes — Full Page**. Both Marathi and English versions are available.

Only approved, published `.xlsx` records have download links, and the files remain in your existing Supabase private `beneficiary-files` bucket until the secured download endpoint signs a short-lived URL. It is an **attachment download**, not an importer of workbook cells into the site.

## Admin: Upload footer logo at bottom of every page

1. Go to **Admin → Your Village → Village Settings**.
2. Scroll to the **Footer logo — bottom of every page** section near the very end, just above Save.
3. Choose **Upload footer logo** (JPG/PNG/WebP); inspect the preview. You can also paste an HTTPS image URL.
4. Click **Save village settings**.
5. Refresh the homepage and `/schemes`/`beneficiaries`: the uploaded footer logo appears below the four-column footer and above the copyright line, on every public page.

This footer logo is **independent per village**, stored as `villages.site_settings.footer_logo_url`. Leave it blank to reuse the existing main village logo. The original `logo_url` upload still controls the header and favicon. No SQL migration is needed because `site_settings` is already a JSONB field.

## Publish using the existing Vercel project

Test a preview first:

```bash
vercel link
vercel deploy
```

After checking both public pages and a signed-in admin edit, publish:

```bash
vercel deploy --prod
```

Do not create a new Vercel project unless you specifically intend to host a separate site. Confirm that the CLI is linked to the correct source project and production domain before publishing.

## Verification / limitations

- Node automated tests, including v3.6 routing, logo fallback, XSS protection, and village isolation, passed.
- Static Chromium render checks at 390/768/1024/1440px found no horizontal overflow. The preview shows sample content only, **not** live village records.
- Actual production admin uploads, private storage writes and Safari visual behavior still need checking with your authenticated account.
- The Supabase schema and permissions are unchanged in v3.6. **Do not rerun a database migration** for this update.
